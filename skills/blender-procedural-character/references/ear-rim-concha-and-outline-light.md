## 一、D0：`ear()` 的局部坐标 / 世界坐标混用

### 症状
`ear()` 先把 UV 球 `transform_apply(location=False, rotation=True, scale=True)`，所以
`v.co` 是**以耳中心为原点的局部坐标**（y∈±19mm、z∈±23mm），而 `cx/cy/cz` 是**世界位置**。
原代码写：

```python
ly = (v.co.y - cy) / 0.0190      # 局部坐标减世界坐标
lz = (v.co.z - cz) / 0.0230
r  = math.hypot(ly, lz)          # r ≈ 50，不是 0~1
rim     = math.exp(-((r - 0.82) / 0.22) ** 2)   # ≈ 0
concha  = math.exp(-(r / 0.42) ** 2)            # ≈ 0
```

结果耳轮/耳甲**从未被雕出来**，耳朵是一个光滑扁椭球，而且从代码上一眼看不出问题
（公式本身没错，只是基准错了）。

### 修法（二选一，推荐前者）
```python
ly = v.co.y / 0.0190     # 纯局部基准，r∈[0,1]
lz = v.co.z / 0.0230
```
另一支是先 `transform_apply(location=True)` 再按世界坐标算。**选哪支要写进函数 docstring**，
否则下一个人会重新怀疑。

### 修完的形态自检（打印采样表，别只看整体）
| r | rim | concha | dx = 2.8·rim − 4.2·concha |
|---|---|---|---|
| 0.00 | 0.00 | 1.00 | **−4.20mm**（耳甲中心内凹） |
| 0.40 | 0.03 | 0.40 | −1.62mm |
| 0.60 | 0.37 | 0.13 | +0.48mm |
| **0.80** | **0.99** | 0.03 | **+2.67mm**（耳轮峰） |
| 1.00 | 0.51 | 0.00 | +1.42mm（最外缘，会撑起头最大宽） |

验收判据：**耳轮朝外量 − 耳甲朝外量 ≥ 1mm**，实测 5.05 − 2.29 = **2.76mm**。

### 方向性判据的坑（必踩）
用 `max(abs(v.co.x))` 量"耳甲内凹"会**把朝内的凹陷读成外伸**——左耳（s=−1）朝外是 **−x**，
耳甲把顶点往 +x（朝头）推，`abs()` 一取就把凹陷记成了"更外"。实测会得出
`concha_max|x| 10.70mm > rim_max|x| 9.70mm`、delta **−1.00mm**（结论完全相反）。

正确：按朝外方向取，`outward = -v.co.x`（左耳），再比较分箱的 p75。

> 通用规则：**凡"凹陷/外凸"类判据，先定朝外方向，再用带符号的投影量**，
> 不要先取绝对值。

### 修完头宽会反向变化（与预期相反，必须复测）
头宽达标（0.2139）**全靠耳外缘**（`HEAD` 表本体只有 0.2062，低于下限 0.212）。
但修好 rim 后耳轮是**外推**，头宽不是变窄而是**变宽**：

| 状态 | 头宽 |
|---|---|
| bug 态（rim/concha≈0） | 0.2139 |
| 修好 rim/concha，耳厚仍 0.0062 | **0.2182（超上限 0.218 共 0.2mm）** |
| 耳厚 `scale x` 0.0062 → 0.0052 | **0.2172 ✅** |

补偿要调"那一路"：耳片 `scale x` 影响最外点是因为最外点 x' 由
`sqrt((rx·cosθ)² + (rz·sinθ)²)` 合成（θ 是耳的 Z 轴旋转 14°），
所以降 x 半径约 1mm 换回单侧 0.7mm。

**规则：任何"bbox 达标靠附属部件"的模型，改那个部件前先写死"改完必须复测 bbox"，
并且要准备好两个方向的补偿量（可能变宽也可能变窄）。**

## 二、C4 轮廓光：在本管线**结构不可达**（不要硬凑数字）

### 试过的全部组合（深色区轮廓亮带恒为 0）
| 变量 | 取值 |
|---|---|
| rim 位置 | 正后 (0.8, 2.4, 2.0) → 左后上 (−2.2, 2.0, 2.2) |
| rim 强度 | 55 → 80（DESIGN）→ **200** → **320W** |
| rim size | 1.0 → 0.8 |
| 验收对象 | 藏青裙 z 0.65~1.05 / 头发 z 1.40~1.53（深色），排除白衬衫/皮肤 |
| 结果 | 所有机位所有强度 **p50 = 0px**（p90 的 10 全是裙褶/发丝，不是轮廓） |

### 剖面证据（这是结论的核心，比"看起来没有"有力）
对每个边界，先跳过 3px 描边暗带，再看内侧：

- 裙边 24~32 vs 主体内侧 40 → **边缘更暗**
- 发边 20~30 vs 主体内侧 30~50 → **边缘更暗**

### 三层机制
1. 轮廓边缘是**掠射面**，Diffuse ≈ cosθ → 0，rim 照上去也就是 0 附近；
2. toon 三档 ramp 把这点低亮度**压进 shadow 档**（比主体更暗）；
3. C1 的 3px 黑描边占据轮廓**最外缘**，即便有亮带也被盖住。
4. 白衬衫/皮肤已在 light 档 227（接近上限），深色区边缘又被 ramp 压暗 → 两端都没有对比度余量。

### 结论（写给用户决策，不写"已优化"）
**描边与轮廓光在本管线互相抵消，必须二选一：**
- 保描边 → 删掉 rim 项（当前态）；
- 保轮廓光 → 去掉 Solidify 反法线壳，改用 Freestyle / 后期 Sobel（DESIGN 方案 B）。

### 判定不可达前要做的对照（证明不是参数没调对）
- 强度至少扫到 4 倍 DESIGN 值（55/80/200/320）；
- 灯位至少换一次（正后 → 侧后），并 `look_at` 重设朝向；
- 判据先排除浅色主体（白衬衫/皮肤），否则测的是"主体已饱和"；
- **同时重测 C3 四项**，确认 rim 有没有污染色阶基线。本轮 rim 在背后，C3 全程稳定
  （p50 195.0 / p95−p50 32.0 / p50−p5 26.8 / ≥228 4.8%），所以可以判定"不是强度问题"。

## 三、rim 判据本身：先跳过描边，再限定深色主体

两处会让判据恒为 0：

```python
# 错：从边界第 1 个像素开始找亮像素 → 第一个就撞到 3px 黑描边
for k in range(1, inner + 6): ...

# 对：
# 1) 先 skip 连续暗像素（<70）跳过描边
k = 0
while k < skip_dark and lum[y, xb + d * (k + 1)] < 70.0:
    k += 1
# 2) 要求边界内侧前 4px 的均值 < subject_max（深色主体），否则这行不算
if subject_max is not None:
    base_lum = mean(lum[y, xb+d*(k+1) : xb+d*(k+5)])
    if base_lum > subject_max:   # 150 左右能把白衬衫/皮肤排除
        continue
# 3) 参照亮度取更内侧（25~45px），量紧跟其后的连续亮带
```

## 四、"手 vs 脸"这条判据本身是错的（跨光照方位比较）

### 错在哪
"手与脸亮度差 ≤5"把**光影方向**当成了**材质不一致**。key 灯单侧时，
背光侧的手天生就该更暗。实测：右手 vs 脸 11.7~14.8，左手 vs 脸 0.1~4.7 ——
同材质、同图，差异全部来自方位。

### 改法
- **主判据：手 vs 同侧前臂 ≤8**（同一条手臂、同一光照方位）；
- **参考值**：手 vs 脸、左手 vs 右手（只作"光影差异"报，不作缺陷）；
- **ROI 取掌背 z 0.760~0.825**，不含手指：指缝里的描边与 AO 会把中位压低，
  那是几何效应不是肤色差异（同一模型换 ROI 从 9.6 降到 6.8）。

实测：右手 6.8 ✓ / 左手 2.0 ✓；参考 手−脸 11.7/2.1、左手−右手 13.8。

### 判断"到底是材质还是光照"
看像素落在哪一档（用 skin 三档最近邻分类）：
- 若所有像素都落在三档内、只是 shadow 占比更高 → 光照；
- 若落在三档之外 → 材质没接上。

## 五、正交反投影的两个前提（做 ROI 前必须确认）

1. **相机必须完全水平**：`loc.z == target.z`。差 0.0034m / 2m（0.097° 俯仰）就够让
   z 反投影偏 0.5mm ≈ 1.3px。改造前先看机位参数，别拿斜视机位算 ROI。
2. **只有正对机位能做世界↔像素换算**：
   `px = w/2 + x·s`、`py = h/2 − (z−zc)·s`，`s = res_y / ortho_scale`（px/m）。
   q34 / side 机位只能做扫描线宽度，不能定位 ROI。
3. **验证入口要先核实它到底建了什么**：本轮任务书说 "m3_look 已挂全套描边与材质"，
   实际它只 `build()` 了 head+body。验深色区轮廓时必须先给入口补 `hair`/`outfit`，
   并新增一个正对全身机位（`560×900 / ortho 1.80 / 中心 z 0.86`）供手部 ROI 反投影。
   **别假设入口名 = 内容**。
