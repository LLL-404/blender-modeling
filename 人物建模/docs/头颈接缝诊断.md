# 头颈接缝诊断（2026-11-05）

> BOSS 问「头和脖子连接处为什么会这样」。**没收到附图**，我按项目里现有的

> 状态：**诊断完成，未改模型、未改判据**。

---

## 0. 结论先行

**不是「缝」，是四个独立的东西叠在一起。**

| # | 根因 | 证据 |
|---|---|---|
| 1 | 头和身体是**两个独立对象**，从不同脚本分别生成，**从来没有融合** | `m1_body.py` 出 Body（含颈柱），`m2_head.py` 出 Head；两者只摆在同一坐标系 |
| 2 | 颈柱是一根**等粗圆柱 + 平顶封盖**，头骨底部是**收尖的下颌超椭圆**，截面形状完全不同 | 下表 z=1424 / 1427 两行 |
| 3 | 为保证不露缝，颈柱被**硬插进头骨 9.17mm** —— 用穿模代替过渡，正面反而更明显地鼓出下颌两侧 | `head_body_gap = −9.17mm` |
| 4 | `voxel_remesh(5mm)` 只融 **Body 内部**（躯干 / 颈 / 四肢），Head 从不参与 | `lib/body.py:build()` |

所以视觉上是「**一根平口管子顶着一个尖下巴**」：正面脖子比下颌宽、侧面脖子又比头骨窄，
中间只有一条硬切线。领口和头发遮住了大半，3/4 视角仍露。

## 1. 实测数据（`scripts/probe_neck_joint.py`，只读）

Head = `head_base()+sculpt()`（纯颅骨）；Body = `body.build()`（含 5mm 体素重网格）。
同一批 z 高度分别切平面求交，量交点包围盒。

| 项 | 值 |
|---|---|
| Head z 范围 | **1421.72 ~ 1680.00 mm** |
| Body z 范围 | 0.00 ~ **1430.88 mm**（颈部顶） |
| `head_body_gap` | **−9.17 mm**（负 = 插入，没有可见缝） |

| z (mm) | Head 宽/深 (mm) | 颈柱 宽/深 (mm) | `Δw` | `Δd` |
|---:|---:|---:|---:|---:|
| 1418.00 | 无（还没到下巴） | 78.5 / 78.2 | — | — |
| 1421.70 | 无 | 77.2 / 77.8 | — | — |
| **1424.00** | **26.2 / 70.4** | **75.7 / 76.9** | **+49.5** | +6.5 |
| **1427.00** | **36.9 / 87.2** | **73.5 / 73.9** | **+36.5** | −13.2 |
| 1430.90 | 48.3 / 101.5 | 无（颈柱到此结束） | — | — |
| 1445.00 | 82.3 / 126.5 | 无 | — | — |

**读法**：

- 颈柱从 1418 到 1427 几乎不变粗（78.5 → 73.5 mm），就是一根直管；`tube()` 默认
  `cap_end=True`，顶端是一个**平的椭圆盖**（`out/m1_body_side.png` 里那个平顶就是它）。
- 同一高度头骨是收尖的下颌：z=1424 时正面只有 **26.2mm** 宽，颈柱却有 **75.7mm**
  → 正面每侧鼓出约 **25mm**，接近 3 倍。
- 侧面反过来：z=1427 时头骨深 87.2mm，颈柱 73.9mm → 每侧凹进约 6.6mm。
- 于是「正面宽出来、侧面缩进去」同时发生，接缝处必然是一圈台阶，不是平滑过渡。

## 2. 为什么会设计成这样（代码层面的历史）

`lib/body.py:neck()` 的注释把来龙去脉写得很清楚：

> `head_to_body_ratio` 是可调旋钮，头缩了下巴会上移（6.505→7.5 时从 1.3710 抬到 1.4039），
> 而颈柱原来钉死在 1.394 —— 实测在下巴底下留了 8.7mm 的缝，头看起来是浮在脖子上的。
> 这里取 `head_rows()` 第一环的 z（头骨最低截面的高度）+ 8mm 插入量。

也就是说：**上一轮修的是「浮起来的缝」，手段是「插进去」**。z 方向确实修好了
（`head_body_gap` 从 +8.7 变成 −9.17），但**横向截面匹配从来没被当成判据**，
所以「管子顶尖下巴」的形态一直留着。

`lib/appearance.py` 的 `head_body_gap` 只算
`头底 z − max(颈部区域顶点 z)` —— 一个一维量，判不出 `Δw=+49.5mm` 这种事。
这是「判据只量宏观」的老问题在本处的又一例。

## 3. 为什么判据没抓到

| 现有判据 | 量什么 | 漏了什么 |
|---|---|---|
| `head_body_gap` | z 方向间隙 | 横向截面是否匹配 |
| `neck_visible` / `neck_over_head` | 脖子露出高度 / 占头长比（96.7mm / 0.3745） | 形状、曲率、台阶 |
| `spec/reference.json` 14 条 | 头身比、腰肩比等宏观比例 | 接缝 |
| A2 五条 | 五官几何 | 接缝 |
| 视觉闸门 3 条 | 画面信息密度 | 接缝 |

**补一条就够**：`neck_joint_max_dw` = 颈部重叠区内 `|颈柱截面宽 − 头骨截面宽|` 的最大值，
要求 ≤ 5mm；同再加一条 `|Δd| ≤ 5mm`。`out/neck_joint.json` 已经把逐层数据算好了，
直接可读。

## 4. 三层修法（按代价，没动代码）

| | 做法 | 代价 | 判断 |
|---|---|---|---|
| A 遮 | 领口 / 头发盖住接缝 | 0 | 已经部分生效，3/4 视角仍露；不解决根因 |
| **B 参数化过渡环（推荐）** | 用 `out/slices.json` 的逐层截面驱动颈柱顶 3~5 层控制环，让颈柱的圆形截面**渐变**到下颌的超椭圆；顺带 `cap_end=False`（反正插在头里，平盖没用） | 新增一个 L2 部件，不动 Head/Body 的拓扑、UV、权重、描边 | 符合「分部件 + 参数合同」，可定量验收（同高度 `Δw/Δd ≤ 5mm`） |
| C 真融合 | 把 Head 加进 `voxel_remesh` 或走 SDF smooth-union | 拓扑/UV/权重/描边全重做；5mm 体素还会抹平 1~2mm 下颌细节 | 前两轮调研已判「局部 ROI 可行、整头不可行」，现在 `flow` 0/6 过闸，**不推荐** |

**B 的具体口径**（从实测数据反推）：颈柱顶宽 73~78mm，而头骨要到 z≈1443mm
才有 78mm 宽。要么把颈柱插到 z≈1443（深 12mm，仍在头骨内部不会外露），
要么在 z=1424~1431 把颈柱收细到 ≤48mm —— 但后者会让脖子只有头宽的 22%，
显得过细。**正确做法是两者都不做，而是加一段过渡面**：
在 z=1424~1445 之间让截面从「颈柱圆」连续变到「下颌超椭圆」，
这正是切片数据能直接给出的东西（与 `docs/模型切片方法.md` 呼应）。
