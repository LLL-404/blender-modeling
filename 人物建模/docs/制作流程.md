# 制作流程（2026-11-04 起）

> 一句话：**一个部位一个部位做。建完就量，量完就看，四样都过才进下一个部位。**
> 执行器是 `scripts/flow.py`，工序表是 `spec/parts.json`。这份文档解释规则，不重复数字。

---

## 1. 为什么改

上一轮不是参数没调好，是流程允许「没判」冒充「判过了」：

| 旧流程 | 后果 |
|---|---|
| `build.py all` 一口气建完 6 步，最后才验收 | 第 4 步方向错了，前 3 步的工全废 |
| 判据只判「有没有」（面数、净空、权重和） | 71 PASS / 0 FAIL 与「模型是一顶灯罩」同时成立 |
| A2 面部、C 三渲二两个探针零判定（`PASS=0 SKIP=14` / `SKIP=35`） | 被当成 OK 混进合计 |
| `spec/deliver.json` 的 `why` 手写「脸型、五眼、发型轮廓」 | 这三项从来没被量过 |
| 目标值散落在探针、DESIGN、spec 三处 | 头身比改 7.5 之后，探针还在按 6.5 的目标打印 |

新流程只做一件事：**把「过」定义成一组有判定、有证据、不过期的记录，别的都不算。**

## 2. 工序表

顺序即工序。上一部位不是 PASS，下一部位不能算可交付（`flow status` 会标「上游未过」）。

| 序 | 部位 | 建什么 | 自动闸门 | 人眼复核 |
|---|---|---|---|---|
| 1 | `body` 身体素体 | `m1_body.py` | A1 手/脚探针（18 条） | 比例、手、脚、站姿 4 条 |
| 2 | `face` 头与脸 | `m2_head.py` → `m3_look.py` | A2 五官几何（5 条）+ C 三渲二（8 条） | 脸型、五官位置、侧面体积、眼睛 4 条 |
| 3 | `hair` 头发 | `m4_hair.py` | D 发型细节探针（11 条）+ 图像指标 3 条 | 剪影、头顶、侧面、发丝 4 条 |
| 4 | `outfit` 服装 | `m5_outfit.py` | A4 服装净空探针（11 条） | 穿模、层次、裙褶 3 条 |
| 5 | `rig` 骨架 | `m5_rig.py` | B 骨架探针（31 条）+ 14 条比例 + 视觉闸门 | 四姿势、手、头发裙摆 3 条 |
| 6 | `asset` 资产化 | `m6_asset` → `bake` → `export` → `multiview` | 资产审计 + 16 机位 | 破面、glb 回读、去描边 3 条 |

改哪一部位的代码，就只重跑哪一部位。`build.py all` 仍保留，但它只是「不带闸门的重建」，
不能作为交付依据。

## 3. 闸门规则（机器执行，不是口头约定）

| # | 规则 | 代码位置 |
|---|---|---|
| 1 | 任一闸门项 FAIL → 本部位 FAIL，不进下一部位 | `flow.evaluate` |
| 2 | 探针 `PASS=0` 且 `FAIL=0` → **零判定 = FAIL**，不是 SKIP | `flow._probe_gate`、`check.py` HOLE |
| 3 | 探针 PASS 数少于 `min_pass` → FAIL（防止悄悄少判几条） | `flow._probe_gate` |
| 4 | 证据图必须比全部源文件新，否则 STALE | `flow._stale_reason` |
| 5 | 人眼复核必须逐条 PASS/FAIL 且写「看到什么」；缺一条 = 未签收 | `flow._review_state` |
| 6 | 复核时间必须晚于证据图，否则视为没看新图 | `flow._review_state` |
| 7 | 已知例外必须写进 `exceptions` 并带 `expires`；过期照常 FAIL | `flow._exception_hit` |
| 8 | 改了本部位的工序定义或判据文件，旧记录过期；判定逻辑版本变化同样作废 | `flow._stale_reason` |

状态含义：

| 状态 | 意思 | 下一步 |
|---|---|---|
| `PASS` | 自动项全过 + 复核全过 + 证据新鲜 | 进下一部位 |
| `FAIL` | 有判定没过 | 改模型，重跑本部位 |
| `NEEDS-REVIEW` | 自动项过了，人眼还没签收 | 看图，写 `review.json`，`check` |
| `STALE` | 记录比源码/证据旧 | 重跑本部位 |
| `NOT-RUN` | 没建过 | `flow run <部位>` |

## 4. 判据从哪来：有真值 vs 没真值

**有真值（可以自动判）**

| 来源 | 判什么 |
|---|---|
| `spec/reference.json` | 7.5 头身、头长、颈长、腰髋比、肩头比、裙摆锥度等 14 条比例 |
| `spec/face.json` | 鼻尖前伸、嘴宽/脸宽、内眼角间距/眼宽、耳高、面中法线（来自 DESIGN §3.1 A2 行） |
| `spec/visual_gate.json` | 头发明暗跨度、发束条纹周期性、脸部细节密度（基线由参考图自身算出） |
| 探针 | 手/脚趾分量、服装净空、权重和、屈指边长比、裙褶相位 |

**没真值（只能人眼，不许假装自动判）**

这张参考图是 **3/4 视角、头部倾斜、单手遮脸** 的插画。它能量：

- 粉色头发的颜色、明暗层次、发束密度
- 发型类型（中分、露额头、发梢到下颌）
- 配色关系（发色 / 肤色 / 服装的明度对比）
- 画面信息密度（贴图级细节有多少）

它**量不了**：

- 正面眼距、嘴宽、脸宽 —— 透视和头部旋转会改变这些比例
- 三维轮廓、鼻梁高度、下颌深度 —— 单视图没有深度
- 发际线精确位置 —— 被刘海遮挡

所以：**几何真值来自设计目标，不来自这张图。** 拿这张图当正视图去反解五官间距，
会得到一个「在 3/4 视角下凑对、转正就错」的解。

**观察项**：`silhouette_iou`（头发剪影 IoU）目前只记录不拦 —— 单张 3/4 参考图
不能给正面剪影定阈值。等有了正视参考图再升级成闸门。

每条新判据加进来之前必须回答一句：**它能拦住什么明显很烂的产出？**
答不上来就别加（`visual_gate.py` 的教训：Canny 密度奖励粗线，不奖励细节）。

## 5. 一次完整的循环

```bash
# 1) 建 + 跑探针 + 判自动项
python scripts/flow.py run body

# 2) 看图（模板会列出证据图和清单）
python scripts/flow.py review body

# 3) 写 out/flow/body/review.json（见下一节）

# 4) 按复核重判，不重建
python scripts/flow.py check body

# 5) 看总表，写交付用的汇总
python scripts/flow.py status --write
```

`run` 停在 `NEEDS-REVIEW` 是正常的：它在等你（或 AI）真的打开图看。
`run all` 按工序推进，第一个没 PASS 就停 —— 这是设计，不是故障。

## 6. 复核怎么写

文件：`out/flow/<部位>/review.json`

```json
{
  "part": "hair",
  "at": "2026-11-05T00:10:00",
  "images": ["out/m4_face_front.png", "out/m4_face_q34.png", "..."],
  "items": [
    {"text": "<与 spec/parts.json 的 review 条目逐字一致>",
     "verdict": "PASS",
     "note": "中分缝在正中，额头露出约 1/3，发梢到下颌，左右发量接近"}
  ]
}
```

硬规则：

- `items` 条数、顺序、文字必须和工序表一致；少一条按「没看」处理
- `note` 必须写「看到什么」，不写「看起来不错」
- 发现缺点就判 FAIL，并在 note 里写清位置（左/右、正/侧、哪一面）
- `at` 必须晚于证据图；改了模型要重新看图、重新写

**复核不是打分，是找茬。** 判 PASS 的前提是「找不到明显问题」，不是「没有大问题」。

## 7. 失败处理

| 情况 | 做法 |
|---|---|
| 一处不过 | 只改这一处，重跑本部位 |
| 同一问题改 2 次还不过 | 停下：列出每种改法+依据+没验证的假设，换方向；不许加第三个变体 |
| 越改越差 | 回退到上一版，把改动拆成更小的两步 |
| 判据本身可疑 | 先改判据并写理由，再改模型；不许为了过闸门调阈值 |
| 确实做不到 | 写进 `exceptions`，带 `reason` / `todo` / `expires`，到期自动变红 |

**禁止**：为了让 `flow status` 变绿而删判据、放宽阈值、把 FAIL 改成 WARN、或者不写复核直接 `check`。

## 8. 与交付的关系

`scripts/deliver.py` 新增 `flow` 来源（`out/flow/summary.json`），两个目标都要求全部部位 PASS。
原来的四套判据（外观 14 条、视觉闸门、16 机位、资产审计、六探针）保留，作为零件被工序闸门引用；
它们单独全绿不再等于可交付。

```
进游戏   = body/face/hair/outfit/rig/asset 全 PASS + 资产审计 + 16 机位
进作品集 = 上面全部 + 14 条比例 + 视觉闸门（对参考图）
```

## 10. 边界

- 自动判据只覆盖「能算的量」。过闸 ≠ 像；不过闸 = 一定不够格。
- 620px 的渲染里，手指、脚趾、睫毛接近可分极限；细节复核要配近景机位。
- `flow` 不替你判断审美。它只保证：**你说「过了」的时候，有图、有数、有时间戳。**
