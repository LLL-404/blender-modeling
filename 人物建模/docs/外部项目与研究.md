# 外部项目与研究盘点：参考图 → 3D 二次元角色（2026-11）

> 目的：别再自己造轮子。把「一张插画变成可用的 3D 角色」这条链上已经存在的项目、论文、数据列清楚，
> 标明**许可、硬件、能不能落到我们这套 Blender 工程**。所有条目均按仓库页面/论文页实际内容记录；
> 页面没写的就写「未写明」，不猜。

## 0. 一句话结论

| 结论 | 依据 |
|---|---|
| 头发这一环已经有**现成可用的开源生成器**（HairDeck，Apache-2.0，2026-11 起支持 Windows），产出格式与我们 `lib/haircard.py` 的表示法一致 | HairDeck README / HF 模型页 |
| 「整链」方案（Charakuru）已经存在，但它把 3D 生成外包给 Tripo（付费），代码不可自由复用 | Charakuru README / GIGAZINE 报道 |
| 学术路线（StdGEN / SeparateGen / PAniC-3D）质量最好，但**权重许可、显存、数据**三道门槛，本机 6GB 笔记本基本吃不下 | CVPR/ICCV 论文页 + 仓库 license 字段 |
| 真正能立刻借的还有**数据与流程**：SC-Anime 的分部件渲染脚本（Apache-2.0）、awesome-astra 的九视图验收流程（MIT） | 两个仓库 README |

## 1. 先对齐：我们缺什么

| 环节 | 当前状态（本工程实测） | 外部能补什么 |
|---|---|---|
| 头发 | 25 张 hair card + alpha 发丝贴图；人眼判定「粗叶片」 | HairDeck 直接生成卡片+弹簧骨；CHARM 提供表示法与数据 |
| 脸 | 几何线稿 + 0.4mm 薄片，`face_edge_density` 0.0767 < 0.0795 | 学术方案（PAniC-3D）证明体渲染可行，但无许可证；实务上仍是「贴图脸」更划算 |
| 身体 | 5mm 体素重网格，硬边被磨圆；提精度会让绑定回归超标 | SC-Anime 的多部件 VRoid 数据可作拓扑/比例参照 |
| 整链 | 我们自己做「参数 → 网格 → 判据」 | Charakuru 是同类工程，可抄它的检查点设计，不是抄代码 |
| 验收 | 16+7 机位、外观 spec、视觉闸门、剪影 IoU | awesome-astra 的「九视图 + 灰模先验 + 多视图验收」 |

## 2. A 类：可以直接换掉某个零件的生成器

### A1. HairDeck —— 单图 → 发卡 + 弹簧骨（**最值得试**）

| 项 | 内容 |
|---|---|
| 出处 | 清华 / CMU / CUHK，arXiv 2610.40599，2026-10-30 发布 |
| 许可 | 代码与 checkpoint **Apache-2.0**；SAM 3、DINOv3 为 gated，各自许可 |
| 平台 | Linux x86-64、**原生 Windows（2026-11-02 起）**、Apple Silicon（MPS） |
| 依赖 | Python 3.12、PyTorch 2.8、CUDA 12.8、一块 NVIDIA CUDA GPU；Windows 版支持 automatic model offload |
| 显存 | **未写明**（README 没有给具体数字） |
| 输入 | 一张角色图 |
| 输出 | `cards_seed*.json`（卡片几何）、`chains_seed*.json`（弹簧骨链）、`hair_seed0.glb`（逐卡 UV + 发色）、`*_nohead.glb`、`avatar_seed0.vrm`、`turn_seed0.mp4` |
| 贴图 | **没有贴图文件**，只有逐卡 UV 与发色 —— 发丝纹理要自己补 |
| 训练数据 | CHARM 数据集 + 角色 VRM；图像训练含合成外观增强 |
| 相对前作 | 比 CHARM 快 33×，Chamfer 距离降 44%（作者自测，CHARM 测试集） |

**对我们的意义**：它输出的就是「一组卡片 + 每卡控制点/宽度/朝向」，和我们 `lib/haircard.py`
的 5 参数控制点表示同源。**可以整块替换现在的头发**，再把我们的 alpha 发丝贴图接上去。

**风险**：① 6GB 显存未经验证（有 offload，可能能跑）；② 要下 SAM3 / DINOv3，需 HF 账号接受条款；
③ 权重与依赖体积大；④ 只出卡片，不出贴图，纹理仍要我们自己做。

### A2. CHARM —— 我们的头发表示法的来源

| 项 | 内容 |
|---|---|
| 出处 | SIGGRAPH Asia 2025，arXiv 2509.21114 |
| 许可 | 仓库 **GPL-3.0**（58 stars，2026-04 后未更新） |
| 数据 | AnimeHair，3.7 万套带分离卡片的二次元发型；**原始 3D 不可再分发**，须按 PAniC-3D 指引自行下载 VRoid 数据再用它的脚本处理 |
| 表示法 | 每张卡片 = 一串控制点，每点 5 个参数（位置 + 宽度 + 厚度）——我们已在用 |

**对我们的意义**：验证了「控制点 + 卡片」这条路是对的；GPL-3.0 决定它只能进内部工具，
不能进闭源产品。数据下载链路太长，不划算。

### A3. PAniC-3D —— 单张插画重建二次元头

| 项 | 内容 |
|---|---|
| 出处 | CVPR 2023，832 stars |
| 许可 | **无许可证**（GitHub API `license: null`）→ 默认保留所有权利，不能商用、不能改后分发 |
| 运行 | Docker + GPU；11.2k VRoid 模型 + 1k VTuber 插画 + AnimeRecon 基准 |
| 现状 | 2023-06 后未更新 |

**对我们的意义**：只能读论文。它的结论有价值：插画要先把**描边填掉**（line-filling）再重建，
否则非真实感轮廓线会被当成几何。我们现在的脸是反过来的（用几何画线），方向正好相反。

## 3. B 类：整链（一张图 → 可绑定角色）

### B1. Charakuru —— 和我们目标几乎一样的同类工程

| 项 | 内容 |
|---|---|
| 仓库 | `nanocle/Charakuru`，1,373 stars，2026-11-02 仍在更新 |
| 许可 | GitHub 标记 `NOASSERTION`（自定义）；公开报道称源码可得、按收入门槛授权，**年营收/累计融资超 1 亿日元需另签书面协议** |
| 依赖 | Node 22+、Chromium 浏览器、**Codex**（图像生成 + 浏览器控制）、**Tripo 账号（付费）**、Blender 5.2 + VRM Add-on + Blender MCP |
| 流程 | 插画 → agent 画 8 张四视图（头含发 / 身体各 4 向）→ Tripo 出 4 个候选 → 选型 → Blender 绑骨/权重/弹簧 → 导出 VRM 1.0 |
| 人只做 5 件事 | 导入图、审图、选候选、调比例、查动作；其余由 agent 执行 |
| 工程形态 | `AGENTS.md` + 9 个 skills + 本地审核 app + 单一 `project.charakit` 状态文件 |
| 已知限制 | 早期版本无表情/眼球运动（现已有 Expressions 标签）；文档由 AI 写；不接受 PR |

**对我们的意义**：不是拿代码，而是拿**架构**：
① 「人在检查点做视觉判断、agent 只执行」的分工；② 单一项目状态文件避免 final2 堆积；
③ 四视图 + 候选选型的产物组织。这三条正好对应我们「判据全绿但人眼不合格」的老问题。

### B2. StdGEN / SeparateGen —— 学术最强，但落不到本机

| 项目 | 许可 | 硬件 | 备注 |
|---|---|---|---|
| **StdGEN**（CVPR 2025，S-LRM） | 代码 Apache-2.0；**checkpoint 许可需在 HF 页确认**（此前记录为研究用途） | 本轮未核实，此前记录 ≥8GB 显存 | 3 分钟出「身体/衣服/头发分离」的角色；分解质量是目前最好的 |
| **SeparateGen**（ICCV 2026 投稿） | 代码「将公开」 | 未写明 | 贡献 **SC-Anime**：7,580 个带部件级标注的二次元角色 |

两者都需要多视图扩散 + 大重建模型，6GB 笔记本跑不动；许可也不支持直接商用。

## 5. 补充：轮廓 → 3D 的研究（对应上一轮 SVG 试验）

| 方法 | 出处 | 做法 | 局限 |
|---|---|---|---|
| **Teddy / 轮廓膨胀** | Igarashi et al., SIGGRAPH 1999 | 2D 闭合轮廓 → 三角化求中轴 → 中轴按到边界距离抬高 → 圆润实体 | 只能出「团块」，出不了薄片、镂空与方向性结构 |
| **Balloon shapes** | Vicente & Agapito, 3DV 2013 | 固定体积约束下最小化表面积（`E(u)=∫√(1+\|∇u\|²)`），解出一个贴合轮廓的高度场 | 对细长结构（脖子、手指）失效，需要额外先验项才能鼓起来 |
| **Monster Mash** | Dvorožňák et al., 2020（ETH） | 单视图分层涂鸦 → 每层膨胀 → 自动蒙皮，可动画 | 本质仍是「厚片叠加」，侧视是分层纸板 |

**结论**：这条路线的数学是「在轮廓约束下解一个最小面积 / 固定体积的曲面」，产出必然是**气球状**。
头发（有方向、有镂空、几十片薄壳）和五官（有凹陷与转折）都不是气球。所以 SVG 只能当**约束**，
不能当几何来源 —— 与上一轮实测一致：挤成 5 cm 薄片后，正面像、侧面是一块板。

## 6. D 类：同类工程与协议层

| 项目 | 许可 | 说明 |
|---|---|---|
| `ahujasid/mcp-for-blender`（原 blender-mcp） | **MIT**，33.2k stars | 让任意 LLM 通过 MCP 驱动 Blender：跑 Python、改材质、导资产；已集成 Tripo / Hyper3D Rodin / Hunyuan3D。**Charakuru 就靠它驱动 Blender** |
| `icesixgod/awesome-astra-blender-characters` | **MIT** | 一套 agent skill（中文正文）：九视图参考（8 个水平方向 + 顶视）、先用灰模查脸型/下巴收口/深度、再补五官与头发、固定相机多视图验收、打包重开 `.blend` |

`awesome-astra` 的流程和我们踩过的坑几乎一一对应：
- 「先用正/侧/斜侧灰模检查下巴收口与深度，再完善五官」→ 我们正是先贴线稿后补结构，顺序反了；
- 「九视图参考 + 对齐相机/尺度/关键点」→ 我们只补到 7 台机位，且没有关键点对齐；
- 「分别报告外形、工程、用途三项检查」→ 我们的闸门只报数字，没分这三类。

## 7. 本机可行性（实测：RTX 4050 Laptop **6141 MiB**、驱动 610.47、Windows 11）

| 方案 | 判断 | 理由 |
|---|---|---|
| HairDeck | **可试** | 官方支持原生 Windows + automatic offload；显存未写明是唯一不确定项。本机缺 Python 3.12（现有 3.13/3.14），但 `uv` 已在，可 `uv python install 3.12` 补 |
| CHARM 推理 | 勉强 | GPL；权重与依赖可下，但只出头发点云/卡片，收益不如 HairDeck |
| PAniC-3D | 不建议 | 无许可证 + Docker + 2023 年停更 |
| StdGEN / SeparateGen | 不行 | 显存与许可双重门槛 |
| Charakuru | 可用但要花钱 | 需 Tripo 账号与 Codex；且许可证限制商用规模 |

合计代价（若试 HairDeck）：Python 3.12 + PyTorch 2.8/CUDA 12.8 + 权重与第三方模型，磁盘与下载量在 10~20 GB 量级，
且要 HF 账号接受 SAM 3 / DINOv3 条款。

## 8. 建议：按性价比排

1. **试装 HairDeck（Windows 路径）**，把 `spec/reference/1000139587.jpg` 喂进去，看四组候选里有没有能直接替换现有头发的。
   若成，头发这一环从「自己写几何」变成「选型 + 补贴图」，能省掉整轮参数化。
2. **照 awesome-astra 的顺序重排我们的建模流程**：先灰模定脸型/下巴/深度，再补五官与头发，最后固定机位验收。
   这一步不花钱、不装东西，只改顺序和检查项，但直接针对「脸平、下巴没结构」。
3. **用 SC-Anime 渲染脚本造评测集**：拿 VRoid 模型批量渲染分部件多视图，做我们自己的「像不像」基准，
   比现在拿一张参考图画 IoU 更稳。
4. **Charakuru 只读架构**：把它的检查点机制与单工程文件设计对照我们的 `deliver.py` / 任务清单。
