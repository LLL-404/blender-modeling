# 头部 L2 拆分与参数合同

> 2026-11-05。状态：**phase 0 / 1 / 2 已执行并验证；phase 3（实体化）待做**。
> 机器可读版：`spec/head_parts.json`。本文解释为什么这样拆、每个部件管什么、按什么顺序改。
> 执行记录见 §10。

## 0. 一句话

头从「1 个壳体 + 4 种贴片」拆成 **8 个 L2 部件 + 1 个线稿层**；每个部件 ≤12 个参数，尺寸一律用「占头宽的比例」，位置用「下巴→头顶的比例」，每个参数必须能推动一条可测的 gauge。

---

## 1. 实测：换头身比只放大了头骨，没放大五官

当前头长 **0.2583m**（6.5 头身 / 168cm），上一代是 0.2161m（7.5 头身）。头骨放大了 19.5%，但五官常量还是按旧头写的：

| 量 | 旧头（0.1907 宽） | 当前（0.2246 宽） | 相对变化 |
|---|---|---|---|
| 单眼全宽 / 头宽 | 0.0372 / 0.1907 = **0.195** | 0.0372 / 0.2246 = **0.166** | −15% |
| 眼中心 x / 头宽 | 0.0405 / 0.1907 = **0.212** | 0.0405 / 0.2246 = **0.180** | −15% |
| 嘴宽 / 头宽 | 0.0240 / 0.1907 = **0.126** | 0.0240 / 0.2246 = **0.107** | −15% |
| 耳高 / 头长 | 0.0458 / 0.2161 = **0.212** | 0.0458 / 0.2583 = **0.177** | −16% |

后果：脸越换越大、五官越换越小。这不是审美判断，是比例算出来的。

另外两条一直在的：

| gauge | 当前 | 要求 | 判定 |
|---|---|---|---|
| 内眼角间距 / 眼宽 | **1.177** | 0.85~1.00 | FAIL（旧头就 FAIL，与换靶无关） |
| 面中法线偏离 | 24.60° | ≤25° | PASS，贴上限 |
| 鼻尖前伸 | 9.03mm | 8.5~10.0 | PASS |

结论：**参数不归一化，换一次头身比就崩一次**。这是拆 L2 的第一理由，不是「结构更优雅」。

## 3. 合同规则（写代码前先认这五条）

| # | 规则 | 判定方式 |
|---|---|---|
| 1 | ≤12 个参数/部件 | 数 JSON |
| 2 | 每个参数有单位、默认值、范围 | JSON schema |
| 3 | **±10% 必须推动至少一条 gauge** | 参数扫描：改 ±10%，至少一条 gauge 单调变化；不动 = 假参数，删掉 |
| 4 | 默认值只能来自现有代码或实测 | 每个 `default` 能在代码里找到对应数字 |
| 5 | 每个部件有自己的白模三视图 + 近景 | `*_clay.png`；彩渲不算几何证据 |

第 3 条是防「参数表很好看、改了没反应」的。现在的 `HEAD_RAW` 102 个数字里，很多改 ±10% 在渲染上看不出差别 —— 那种参数不该出现在合同里。

## 4. 归一化怎么落

### 4.1 单位约定

| 后缀 | 含义 | 例 |
|---|---|---|
| `_r` | 占头宽（x/z 尺寸） | `eye_w_r = 0.195` → 眼宽 = 0.195 × 头宽 |
| `z_r` | 下巴 0 → 头顶 1 | `mouth_z_r = 0.199` |
| `_mm` | 前后向凸起/凹陷（雕刻深度，不是尺寸） | `tip_fwd_mm = 12.5` |

### 4.2 眼距这一条怎么修（算给你看）

定义 `e = 单眼全宽/头宽`，`x = 眼中心距中线/头宽`。内眼角间距/眼宽 = `(2x − e) / e`。

- 现在 `e=0.1951, x=0.2124` → `(0.4248−0.1951)/0.1951 = 1.177`（FAIL）
- 目标 0.85~1.00 等价于 `x/e ∈ [0.925, 1.00]`
- **只把眼宽 `e` 从 0.195 提到 0.220、眼中心不动**：`(0.4248−0.220)/0.220 = 0.931` → PASS
- 也就是说：**眼睛放大 13%，不要内移**。这比「把眼距调窄」更符合二次元大眼方向。

这是 phase 2 的第一组候选值，不是最终值；改完要用白模正视图量，不许照渲染图反调。

### 4.3 嘴和耳

| 件 | 当前比例 | 归一化回旧设计比例 | 结果 |
|---|---|---|---|
| 嘴宽 | 0.107 × 头宽 = 24.0mm | 0.126 × 头宽 | 28.3mm（仍落在 10~13% 脸宽内） |
| 耳高 | 0.177 × 头长 = 45.8mm | 0.212 × 头长 | 54.8mm（**超出旧目标 45~50，见 §6**） |

## 5. 迁移顺序（每阶段都必须能单独回退）

| 阶段 | 动作 | 验收 | 回退 |
|---|---|---|---|
| **0 冻结基线** | 不改几何。新增 `scripts/head_baseline.py`：导出 Head 顶点坐标 hash + 每部件 bbox/锚点 + 全部 gauge 现值 | 连跑两次 hash 一致；`spec/head_parts.json` 的 current 全部有值 | 不涉及 |
| **1 纯搬代码** | `lib/head.py` 拆成 `lib/head_parts/{skull,jaw,cheek,brow,nose,lips,eye,ear}.py`，数值一字不改，`head.build()` 只负责拼装 | Head 顶点坐标逐点残差 **= 0**；A2 5 条判定与拆分前完全一致 | 保留原 `head.py` 到 `_bak_head_split/` |
| **2 归一化** | 绝对常量换 ratio；修眼距（眼宽 ×1.13）；嘴宽回 0.126 | A2：眼距 0.85~1.00、其余 4 条不回退；头宽/头长/头深 3 条不回退 | 只回滚参数，不回滚拆分 |
| **3 实体化** | 顺序：眼球+眼睑 → 鼻子 → 嘴唇。每件单独做，做完立刻白模三视图 + 侧视近景 | 侧视能看到眼睑厚度 ≥0.8mm、鼻底有凹、唇体有凸；`inner_eye` 不回退；`flatten_face` 不压平眼球 | 每件独立开关，坏一件只关一件 |
| **4 收尾** | 删旧贴片路径（保留 `face_detail` 线稿）；`flow` 的 face 复核条目改成引用 L2 清单；文档同步 | `flow run face` + `check face` 全过；glb 仍是 5 网格 | 旧贴片代码留到 `_bak`，不直接删 |

## 6. 三件事已定（BOSS 2026-11-05「按推荐」）

| # | 决策 | 落地 |
|---|---|---|
| 1 | 耳高保持绝对 **45~50mm**，不随头放大 | `ear` 部件参数改 `ear_h_mm = 45.82`，不再用 `ear_h_r`；`spec/face.json` 目标不变 |
| 2 | 眼宽放大 **12.8%**、眼中心不动 | `eye_w_r 0.17390 → 0.19614`（基准 head_unit）；`EYE_X` 保留绝对 40.5mm |
| 3 | 只做静态眼球/眼睑实体，**不绑眼睑骨** | phase 3 只加几何，不进 `rig.py` |

**口径修正**：§4.2 的推导用「含耳头宽」，实际代码采用 **head_unit = 2×max(rx of head_rows())**（名义头骨宽，0.213914m，不含耳）。原因：耳是独立部件，用它当基准会自引用。结果一致 —— 眼宽系数 0.17390→0.19614，内眼角/眼宽 1.1774→0.9305。

**已知取舍**：眼中心是唯一保留绝对值的尺寸参数。将来再换头身比，眼宽会跟着 head_unit 变但眼中心不动，眼距比会再漂；届时必须同步重算眼宽系数。这条写进 `spec/head_parts.json` 的 `_rules`。

## 7. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| `hair._cap` 在 import 时读 `HEAD` 快照 | 拆模块时 `HEAD` 消失 → 发帽错位 | 保留模块级 `HEAD`，拆分只搬函数 |
| `look.flatten_face` 有一份独立的 `sz()` 副本 | 头缩放改了但 flatten 没跟上 → 脸被压平 | 拆分时把 z0/z1 改成读 `head.sz()` 或共用常量 |
| `rig.py` 的 head 骨用固定 z | 头变大后骨骼错位 | phase 2 后复测 head 骨 head/tail |
| `m6_export` 按 5 个主网格白名单导出 | 新的 eyeball/lid 独立物体进不了 glb | volume 部件必须在 `head.build()` 里 join 进 `Head` |
| `face_detail` 用 BVH 贴线 | 鼻/唇变体积后线会浮空 | phase 3 每改一件，重跑 `face_detail.conform` 并看近景 |
| 绝对目标值（耳高/嘴宽/鼻深）是按旧头定的 | 归一化后可能「判据全过但比例不对」 | §6 先定目标，再改代码 |

## 8. 不做什么

- **不引入新的外部依赖**（不加 LL3M / BlenderLLM，原因是许可证、精度、以及它们解决的是物体/场景不是角色脸）。
- **不把脸做成贴图**：这一轮先把结构做出来；贴图脸是另一条路线，等结构对了再谈。
- **不一次改 8 个部件**：phase 1 只搬代码，phase 3 一次只实体化一个。
- **不为过闸门调阈值**：gauge 的规则来自 DESIGN/spec，改规则要单独提交理由。

| `probe_cage.py` | 通过（它运行时改 `head.CAGE_GROW_X/Y`，所以这两个变量特意留在门面） |

关键实现：部件函数**返回增量序列**，门面按拆分前的顺序逐个 `dy += e`。浮点加法不满足结合律，若让部件返回「总和」再累加，hash 会变 —— 这是逐位一致的唯一办法。
