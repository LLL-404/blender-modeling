## 一、角色设定基准

### 1.1 风格定位：原神式三渲二 + 日常制服少女

**为什么是这两条，而不是别的：**

| 选择 | 理由（基于现有代码栈，不是审美偏好） |
| --- | --- |
| 原神式三渲二 | `look.py` 已经跑通「Diffuse → Shader to RGB → 三档 ColorRamp → 乘底色 → Emission」这条链，且 `flatten_face()` 已在做脸部法线压平。这是原神管线的核心两件套，**继续沿用的边际成本最低**；换写实渲染等于推翻 `look.py` 全部资产。 |
| 日常制服（白衬衫 + 藏青百褶裙） | 几何复杂度集中在躯干轮廓和裙摆起伏，**不依赖复杂配饰、不做镂空/刺绣/金属件**。参数化建模（截面表 + 放样）正好擅长这类「大面 + 规则褶皱」的形体。换古风/机能风会立刻需要布料模拟或大量手工拓扑。 |
| 6.5 头身少女 | 二次元少女的头身比甜点区是 6.0~7.0；6.5 既保留「头大」的可爱感，又不至于 Q 版化到失去比例表现力。 |

**风格参考（只列可直接对照的技术点，不列「像谁」）：**
- 原神 / 崩坏3 的角色渲染：脸部用**法线压平 + 三档软色阶**，身体用**正常的体积阴影**，两者不是同一套光照逻辑。当前代码只对脸做了压平，身体没有 —— 这是 C2 要做的事。
- 二次元描边：本体 + 反法线外扩壳（Solidify + flip normals + backface culling），**不是**后期 Sobel 边缘检测。后期边缘检测会把布料褶皱也勾成线，脸会脏。
- 头发高光：原神的「天使环」是**视角相关**的横向高光带。当前代码用世界坐标 z 做带，是简化版，可接受，但要修带的位置（见 C4）。
- 制服百褶裙：褶是**径向的等角度折线**，不是正弦波；当前 `outfit.py:67` 用 `amp*cos(pleats*a)` 是对的，但缺少「褶峰更硬、褶谷更软」的非对称。

**6.5 头身的实际做法（与本文初稿的推荐不同，按这个实测版执行）**

初稿推荐「绕几何下巴 z=1.3836 纯放大 ×1.063」。**纯放大不可行**，推导：

- 旧头长 = 1.6180 − 1.3836 = 0.2344；目标头长 = 1.6200 / 6.5 = 0.24923 → 缩放比 **s = 1.0631**。
- 绕 1.3836 纯放大：下巴留在 1.3836，头顶 → 1.3836 + 0.2344 × 1.0631 = **1.6328**。
- 身高变成 1.6328，比目标 1.620 **高 12.8mm**，超出 ±5mm 容差 → **不可用**。

实际方案：**绕 z = 1.5857 缩放 ×1.0631**，数学上等价于「绕 1.3836 放大后再整体下移 **12.7672mm**」：

| 关键点 | 旧 z | 变换 | 新 z | 实测 |
| --- | --- | --- | --- | --- |
| 几何下巴 | 1.3836 | 1.5857 + (1.3836 − 1.5857) × 1.0631 | 1.3708 | **1.3710** |
| 头顶 | 1.6180 | 1.5857 + (1.6180 − 1.5857) × 1.0631 | 1.6200 | **1.6200** |

锚点 1.5857 不是拍脑袋选的，是**联立解**：同时满足「头长 = 0.24923」与「头顶 = 1.6200」的唯一固定点。

**代价（已知取舍，不是缺陷）**：头整体下移 12.7672mm，下巴 1.3836 → 1.3710，于是
- 下巴 → `SHOULDER_Z`(1.295) 的颈长由 **88.6mm 缩到 76.0mm**（−12.6mm）；
- 下巴 → 躯干顶(1.325) 只剩 **46.0mm**；
- 视觉后果：**脖子露出变短、更「贴肩」**。这是买 6.5 头身付的价。**不要为了让脖子变长去调 `SHOULDER_Z`** —— 它会连锁到 `TORSO` 表、肩宽、上臂骨根位置。
- 本项目决定：**6.5 头身优先于颈长**。

**连带同步项**（A2 已做；以后改头必须重做一遍）：`cfg.CHIN_Z` → 1.3712、`rig.py` head 骨的 head/tail、`look.flatten_face()` 的 z0/z1 区间、`hair._cap()`（引用 `HEAD` 表，自动跟随）。

### 1.3 五官设计意图

**眼**
- 形态：杏仁形（`almond()`），上眶半高 18.8mm、下眶 11.0mm，全宽 41.6mm，外眼角上挑 `0.16*w`（≈3.3mm）。
- 目标观感：**上睑厚、下睑细、内眼角收尖、外眼角上翘**。当前上睫毛带宽从内 3.0mm 渐变到外 8.2mm（`head.py:192`），这个渐变的**方向是对的**（外眼角更重），但起始值 3.0mm 偏厚，建议内端降到 2.0mm。
- 眼距：**实测已达标（0.95 眼宽）**。这一条不要再动 —— 详见第四章「眼距定义陷阱」。

**鼻（可读性目标是本文重点）**
- 几何：鼻尖 z≈1.456，鼻梁窄高斯 σ=9mm，鼻头 σ=8.2mm。
- **A 后实测：鼻尖相对额面前伸 9.70mm**（鼻尖 y −0.07771 / 额面 y −0.06801），落在目标 [8.5, 10.0] 中段 ✅。
- 达标靠两条一起改，缺一不可：① 鼻尖推量 0.0105 → 0.0125；② `flatten_face()` 保护带从 `x/0.013 × z/0.016`、系数 0.88 **收窄到 `x/0.008 × z/0.010`、系数 0.75**。只加几何、不收窄保护带，前脸仍会被压成硬边。
- **法线实测**：面中（z=1.4437，中线）法线偏离 −Y **17.77°**（目标 ≤25° ✅）；下颌转折处（z=1.3903）**28.09°**，超过 25°，但那属于下颌面、不属于「面中保护带」—— 判定时把两个数分开，别混算。
- `head.py` 的 `nose()` 7 面四棱锥贴片**仍是死代码，A 阶段没有接入**（靠几何 + 保护带已达标）。D 阶段若做「鼻底阴影带」再决定接入或删除，不要留着误导后续修改。

**嘴**
- A 前：单条带宽横带，宽 30mm（占脸宽 14.8%），厚 1.8~3.4mm，z 1.4305。
- **A 后实测：宽 0.0240 = 脸宽 11.22%**（按 HEAD 表 0.2062 算则 11.64%），目标 [10%, 13%] ✅；上唇/下唇厚度已纠正为「上薄下厚」。
- 嘴角上翘 1.0~1.5mm **未做**，留 D 阶段。

**耳**
- A 前：椭球压扁 (6.2×19×30mm)，高 60mm（偏大 20%）。
- **A 后实测：耳高 45.82mm**（`ear_z_range` = ±0.0229 → 45.8mm），目标 [45, 50] ✅。
- **但耳轮/耳甲实际上是平的**：`head.py:303-332` 里 `v.co` 是物体**局部**坐标，而 `cy/cz` 传的是**世界**位置，两者相减后 `r ≈ 65`，`rim`/`concha` 两个高斯恒为 0 —— 「耳轮外推 2.8mm、耳甲内凹 4.2mm」**从未生效**。A2 只改了耳高，未修此 bug（不在其范围），已登记为 **D0**。
- 后果：耳朵目前是光滑的扁椭球，0.5mm 暗线**没有几何来源**。修 D0 之前，不要试图用描边去「勾」耳轮。

**发束分层规则（写给 Generator 的硬规则）**：
1. 每缕发束是「椭圆截面管」（`_strand` → `tube`），`widths` 传的是**半径**，全宽 = 2×widths。代码注释和视觉判断要统一，别把 0.020 当成 20mm 全宽。

4. 侧发必须**贴着脸颊走**（x 从 0.075 到 0.086），不能飘在外面 —— 当前 z 1.220 处 x=0.092，头半宽 0.101，还在脸内，✅。

### 1.6 配色与材质规范

**先讲清 `toon()` 的数学**，否则会调错：

```
最终线性色 = base × ramp_color
显示色（Standard 视图变换）= sRGB(最终线性色)
```

`toon(name, base, shadow, mid, light, pos)` 里 **`base` 是主色，`shadow/mid/light` 是 ColorRamp 的三档乘数**，不是最终色。`pos` 是 Diffuse 亮度到三档的切分位置。

## 二、技术方案

### 2.1 模块职责边界

| 模块 | 负责 | 不负责 | 关键契约 |
| --- | --- | --- | --- |
| `cfg.py` | 单一比例常量源（HEIGHT/CHIN_Z/各 z 与半宽/RING_SEG/SEED） | 不做几何 | ⚠️ **实际割裂**：`TORSO` 表在 `body.py`、`HEAD` 表在 `head.py`，改头身比要改两处。本文 1.2 的 6.5 头身方案必须同时改 `HEAD` 表与 `cfg.CHIN_Z` |
| `meshkit.py` | 纯几何工具：`superellipse_ring` / `loft` / `tube` / `resample` / `voxel_remesh` / `solidify` / `join` | **不放材质、不放场景、不相机** | 保持无副作用；新增几何工具放这里 |
| `body.py` | 躯干截面表 + 顶点雕塑 + 腿/脚/臂/手 + 体素融合 | 不碰头部、不碰布料 | `sculpt_torso()` 被 `outfit.py` 复用 → **公共契约，改签名必须同步 outfit** |
| `head.py` | 颅骨放样 + 五官 sculpt + 贴片五官（BVH conform）+ 耳 | 不碰头发 | `HEAD` 表被 `hair._cap()` 引用 → 改表必须同步检查发帽 |
| `hair.py` | 发帽 / 后发片 / 发束 / 刘海 / 侧发 / 呆毛 | 不碰头部几何 | 只能用 `tube` 做发片，不能生成封闭块状体 |
| `outfit.py` | 衬衫 / 领 / 袖 / 裙 | 不碰身体几何 | 必须 import `body.TORSO` 与 `body.sculpt_torso` |
| `rig.py` | 21 骨骼 + 最近骨段权重 + 4 姿势 | 不碰几何与材质 | `weight_nearest` 的 `power/keep` 会改变所有姿势观感 |
| `look.py` | toon 材质 / 法线压平 / bloom | 不碰几何（`flatten_face` 只写法线） | `set_all()` 的 key 名被 m2~m5 依赖，不能改名 |
| `shots.py` | 场景 / 灯光 / 相机 / 渲染 | 不做模型 | `render()` 返回路径，`ensure_out()` 建目录 |
| `sheet.py` | PowerShell 拼版 | 不参与建模 | 只用 bytes 解码（已踩过 GBK 坑） |

**验收责任划分**：几何缺陷（穿模/比例/分叉）由 `_probe/` 的几何量测判定；渲染缺陷（色阶/描边/高光）由 Pillow 像素统计判定；两者都不通过就不算完成。

### 2.2 参数化建模的硬约束

1. **截面表驱动**：躯干/头/裙的形体只通过「表 + resample + loft」改变。禁止为了调形手推全量顶点（`sculpt_torso`/`sculpt` 这类**有明确解剖目标的局部推进**是允许的例外）。
2. **体素重网格后不保留尖锐细节**：`body.build(voxel=0.0050)` 用 5mm 体素，会抹掉 <5mm 的特征，且 `smooth(factor=0.5, iterations=5)` 再收缩一次。实测 Body **72,770 顶点**（A1 返工后；A 前为 66,354）。
   - **直接后果**：手指（全宽 6~9mm）、脚趾（全宽 8~12mm）在 5mm 体素下必然糊成一坨 —— 这就是为什么现在「手只有一根圆柱 + 拇指」。
   - **两条出路**：① 把 voxel 降到 2.5mm（顶点 ×8 ≈ 53 万，构建从数秒变数十秒）；② **手/指独立物体，不参与 body 的 voxel 融合**（见 2.4.1，推荐）。**脚可以走 ① 的折中（voxel 3mm 单独融）**，因为脚在画面里占比小。
3. **贴片五官必须 conform 到 BVH 面**：平面生成 → `bvh.ray_cast(x, -0.5→+Y)` → 写回 y → **整体前移 depth（0.0012~0.0038）**防 z-fighting（`head.py:113`）。新增贴片（鼻影、面部阴影带）必须走同一函数。
4. **服装必须复用 `sculpt_torso()`**：衬衫/裙在参数面上做出后，必须应用同一套胸腹推动量，否则胸前必穿。实测 A 后净空 **+15.7 / +16.0 / +14.7mm** 是靠这条保住的（A 前 10.3 / 10.2 / 8.5）。
5. **`join()` 重排索引**：任何依赖面索引的逻辑（材质分配、顶点组）在 join 后都会失效。当前 `outfit.py:87` 已经用「按 z 判材质」规避，新代码必须遵守。
6. **一次只改一类问题**：几何 / 材质 / 服装分开验，改完立刻渲染 + 用量测核对（这是踩过的坑，攒改动会定位不到回归）。

### 2.3 Blender 5.2 API 注意事项（实测，别重踩）

1. **合成器**：`scene.node_tree` **已不存在**。用 `scene.compositing_node_group`（`NodeTree`），没有就 `bpy.data.node_groups.new("Compositing", "CompositorNodeTree")`；输出用 `NodeGroupOutput`，接口要 `ng.interface.new_socket("Image", in_out='OUTPUT', socket_type='NodeSocketColor')`。`look.bloom()` 已按此实现，**照抄即可，别写 `use_nodes`**。
2. **Glare 节点**：改为输入槽 API，`inputs["Type"].default_value = "Bloom"`（枚举是 `Bloom`，**不是** `BLOOM`）、`Quality="High"`、`Threshold`、`Size`（0–1 因子）、`Strength`。旧的 `glare_type/quality/threshold` 属性会抛 AttributeError。
3. **`Shader to RGB` 只在 EEVEE 可用**：Cycles 下该节点不存在，材质会全黑。本管线锁死 `BLENDER_EEVEE`。
4. **自定义法线**：`mesh.normals_split_custom_set_from_vertices(list)` + `polygon.use_smooth=True`。`flatten_face()` 里已经有 `try/except` 兜底，新增法线操作也要包。
5. **`bpy.ops.object.mode_set`** 依赖 active object：`build_armature()` 里先 `bpy.context.view_layer.objects.active = ob` 再切 EDIT，顺序不能反。
6. **`bpy.ops.wm.save_as_mainfile`** 在 `-b` 下可用；保存前如果 armature 还停在 Pose Mode 也不会报错，但**姿势会被存进去**（`m5_rig.py:69` 先 `apply_pose(arm,"rest")` 再存，是对的，别删）。
7. **EEVEE 性能实测**：560×900 / 48 samples 单张 **0.3~0.7 秒**（4 张全部渲染完 <2 秒），整个 `m5_rig.py` 含建模 **10 秒**。所以「改-渲-验」的循环成本很低，**不要攒改动**。
8. **枚举试探法**：遇到不认识的属性先 `dir(obj)` / `obj.bl_rna.properties` / 试探枚举，别照抄旧版本教程。
9. **子进程拼版**：`subprocess.run(..., text=True)` 会因中文路径/GBK 输出抛 `UnicodeDecodeError`，随后 `r.stdout` 为 None 再崩。`sheet.py` 已改成 `capture_output=True` + utf-8→gbk→replace 解码，**保持这样**。

### 2.4 新增模块的设计

#### 2.4.1 手部模块 `lib/hand.py`（新建，A1）

**现状事实**：`body.py:109 hand()` 只有 2 根管 —— 手掌管（3 截面点，radius 25→29→19mm）+ 一根拇指（2 点，12→9mm）。实测指尖/掌心切片 `xy_components = 1`，即**完全没有手指分叉**。

**设计方案**：
- 每只手 = **手掌（1 块扁 box-tube）+ 4 指 + 1 拇指**。每指 **3 段**（近节/中节/远节），段间用「关节球」过渡（半径 +8% 的小椭球），保证弯曲时不出现断口。
- 尺寸（右手，单位为米）：掌宽 42mm、掌厚 14mm、掌长（腕到指根）48mm；指长 食指 26 / 中指 28 / 无名 25 / 小指 20mm；指宽 8 / 8.5 / 8 / 7mm；指厚 9mm；拇指长 28mm、直径 13mm。
- 默认姿态：四指微屈 6°，拇指外展 20°。**不要做完全伸直**（像耙子）。
- **独立物体，不加入 body 的 join**：`hand_L` / `hand_R` 各自 `voxel_remesh(0.0020)` + `smooth(0.3, 2)`（2mm 体素才能留住 8mm 粗的手指），再 `join` 进 `Body` 会再次被 5mm 体素糊掉 —— **绝不能 join**。
- 与手腕的接缝：让手模块的腕口**插入**前臂末端 6~8mm。接缝藏在袖口内，靠遮挡而非融合。
- **A 后验收实测**：指尖判据见下节（首次 4 分量 14mm 深 ✅）；Hands **5,476 顶点**；bbox 厚 21.3 / 宽 60.8 / 长 80.7mm，长宽比 **1.326** ∈[1.0,1.6] ✅；每手 **6 个顶点组**（`palm/index/middle/ring/pinky/thumb`），≥5 ✅。

**取舍**：放弃体素无缝融合，换来 4 指细节。接缝处如果露，宁可加「腕部包边」小环，也不要回到 5mm 融合。

**手腕接缝：第一版失败，第二版靠「前臂渐细变扁 + 掌口加宽」修掉**

- 第一版（A1 首轮）腕部有 **27mm 的环形台阶**：前臂端帽 φ47.1mm vs 手掌 φ20.1mm，形成一圈凸台，近景一眼可见。
- 修复：① 前臂末端由等圆改为**渐细且变扁的扁椭圆 (10.5, 15.0)mm**（厚 10.5 / 宽 15.0），向前臂方向收敛；② 手掌腕口加宽，贴合前臂端截面。
- **A1 返工后实测台阶：厚向 +1.75mm / 宽向 −0.17mm**，阈值 ≤3mm → ✅ PASS。
  （宽向为负 = 手掌比前臂略窄，是正确方向，不算台阶。**台阶必须厚、宽两个方向都测** —— 手是扁的，只看宽方向会把厚度方向的台阶藏起来。）

**指尖判据：旧的「统一 z 带」已废弃，改用「每指末 5mm + 掌底深度扫描」双判据**

- 旧判据实测**极其脆弱**：10mm 带得 3 个分量、12mm 带得 4 个，4 分量只存在于 4mm 薄带里、余量 1.2mm —— **判据本身比被测几何还敏感**，手指微屈 0.5° 就翻结论。**已废，不要再用。**
- 最终口径（`_stageA/a1_hand_probe.py`）：
  1. **每指末 5mm 独立切片**：按顶点组取每根手指自己最末 5mm 的顶点，逐指算 `xy_components`（须 ≥1），再合并算一次（须 **=4**，四指互不连通）。「不共享顶点」由 `REPLACE` 单一归属保证。
  2. **掌底向下 2mm 步长深度扫描**：从 `PALM_BOT_Z` 向下，每 2mm 一档、档厚 2mm，逐档投影算分量数，得「深度:分量数」曲线，取首次达到 4 分量的深度。
- **A1 返工后实测：首次 4 分量在 14mm 深**（打回时为 12mm；前臂末端变细后手部体素化边界变了，属正常漂移）。

#### 2.4.2 脚趾（A4）

- 已实现：`body.foot()` 末端加 3 组趾（大趾 + 2 组合并），整只脚上抬使底面贴 z=0。`m1_body.log` 记录 `[stats] feet lift dz=-1.60mm (只抬脚，不动腿/踝)` —— 只抬脚掌、不动腿长，所以腿长比 0.469 未被破坏。
- **A 后实测：`foot_zmin_mm = 0.0`** ✅（A 前 −11.6mm，踩进地板）。

**脚趾四个口径互证（本项目最典型的「口径决定结论」案例）**

| 口径 | 定义 | 实测分量数 | 结论 |
| --- | --- | --- | --- |
| ① 裸 z 切片 | z∈[4,20]mm，不限 y | **1** | **解剖上不成立**：脚趾必须连着脚掌，投影与脚掌侧壁必然连通，上限就是 1；加趾也不会变 |
| ② z + y 带（主指标） | z∈[4,20]mm ∧ y ≤ 96mm | **3** | ✅ 达标（≥2），133~139 点 |
| ③ 更窄 y 带 | z∈[6,16]mm ∧ y ≤ 90mm | **1** | 带太窄把趾缝切掉，**不可用**，会误判为失败 |
| ④ y=100mm 半带 | y≈100mm，半带宽 1.5mm，看 x-z 投影 | **3** | 交叉验证，与 ② 一致（质心 47.8/77.8/100.2mm） |

**结论：只有 ②/④ 是有效口径。** ① 的上限本来就是 1（不是缺陷），③ 会误判失败。判脚趾用 ②，并用 ④ 交叉验证；**看到 ①=1 不要去「修脚」**。

#### 2.4.3 描边（C1）

**方案 A（推荐）：Solidify + 反法线 + 背面剔除**
- 对 Body/Head/Hair/Outfit 各加一个 Solidify：`thickness = 0.005`（≈2.4px @ ortho 1.85/900px）、`use_flip_normals = True`、`offset = -1`、`use_rim = False`。
- 描边材质：Emission 纯黑（线性 0.02），`mat.use_backface_culling = True`（关键：剔除朝外的面，只显示翻转后的内壳 → 视觉上成为轮廓线）。
- 优点：不依赖合成器、EEVEE 下稳定、每对象线宽一致。
- 缺点：多个对象互相遮挡时，内壳会自遮挡产生「断线」；凹处（腋下、指缝）线会变粗。

**方案 B：Freestyle**
- 优点：真轮廓线 + 可控制笔触（可加线条粗细变化）。
- 缺点：5.2 下 EEVEE 的 Freestyle 支持需要实测；4 张 560×900 图会明显变慢（Freestyle 是 CPU 光栅化后处理）。
- **取舍：先 A，A 的验收不过再考虑 B。不要在 A 未验证前同时上 B。**

**验收**：在纯背景（人物不在背景上的区域）画一条穿过身体轮廓的水平扫描线，找亮度 <40 的连续像素带，宽度必须 ∈ **[2, 4] px**（当前为 0，无描边）。

#### 2.4.4 面部阴影层（C2）

**方案 A：几何贴片（BVH conform）**
- `head.face_shadow()`：生成「下巴下沿 + 鼻底 + 上眼睑下沿」三条带状面，conform 到脸面后前移 0.0008，材质用 `skin_ramp_shadow`（纯 shadow 档色 + alpha）。
- 优点：完全可控、与光照无关、原神就是这么做的（脸部阴影是贴的）。
- 缺点：增加 z-fighting 风险；转头时贴片跟着头转，观察角度极端时会有「贴纸感」；需要 alpha blend（EEVEE 下 `BLEND` 有排序问题）。

**方案 B：材质节点（视角/光照相关）**
- 在 skin 材质里用 `Geometry.Position` 判断是否在脸部区域（`z > 1.38 and y < -0.02`），给 ColorRamp 的 `Fac` 叠加一个偏移 `+0.15`，使脸部比身体更早进入 shadow 档。
- 优点：无额外几何、无 z-fighting、转身自然。
- 缺点：坐标硬编码，头放大 6%（本文 1.2）后必须同步阈值；节点逻辑复杂，调试靠试。

**取舍：B 为主（承担整体脸的「背光柔和阴影」），A 为辅（只做鼻底一道 3~5mm 的硬阴影带，这道线是贴片的高价值场景，因为它的位置是解剖固定的）。**
**验收**：鼻下 ROI（z 1.440~1.452，|x|<10mm）的亮度中位数 ≤ 该图皮肤 p50 − 20；下巴 ROI 的 shadow 档像素占比 ≥ 8%。

#### 2.4.5 头发高光与轮廓光（C3/C4）

- 天使环：当前 `MapRange(0.95→1.66)` → band 位置 0.585/0.845 对应世界 z **1.365 / 1.550**。正确位置应在颅顶下方 1/5 处，即 **z 1.52~1.60**。把 band 的上边界位置从 0.845 改到 0.90~0.92 区间（对应 z 1.59~1.60），并加宽 0.03。
- 轮廓光：`rim` 灯已有 55W。目标是在暗背景上形成 2~6px 的亮边；若不够，把 rim 提到 80~100W 或缩小 size 到 0.8。
- **验收**：头发区域亮度 p99 出现在 z∈[1.52,1.60] 的像素占比 ≥60%；背景侧轮廓亮带宽度 2~6px。

## 三、分阶段路线（A/B/C/D）

### 为什么必须是 A → B → C → D

1. **A（几何硬伤）先做**：手、脚、鼻、脚底落地都是「拓扑/尺寸」问题。如果先做材质（C），每改一次几何，材质验收的全部像素指标都要重测一遍 —— 白干。而且描边依赖几何轮廓，手是圆柱还是 5 指，描边后的观感完全不同。
2. **B（骨架）次之**：骨架的权重依赖几何（手指要指骨、裙子要分带）。A 阶段手部改成 5 指后，B 阶段才可能给指骨加权重。反过来先做 B，A 改手会让全部手部权重作废。
3. **C（质感）再次**：描边/色阶/阴影层是「叠加在正确形体上的渲染层」。形体错了，质感越好越像给畸形上妆。
4. **D（细节）最后**：刘海分组、领型、袖口、裙褶全是锦上添花，任何一项失败都不影响前三个阶段的可交付性。

> 每个阶段结束都必须能出一张可对比的图 + 一组可复现的数字。**没有数字的阶段不算完成。**

## 四、验收方法论（看不到图时的替代验证）

### 4.1 三层证据，优先级从高到低

1. **几何量测（主证据）**：在 `美女.blend` 上跑 `_probe/rig_probe.py`，按 z 切片打印 x/y 范围、连通分量、权重分布。**可复现、不依赖视觉。**
2. **像素统计（主证据）**：Pillow 统计 ROI 的主色占比、亮度分位（5/50/95）、色带宽度。用于材质/描边/高光这类几何量测看不到的东西。
3. **`analyzeImage`（仅旁证）**：**不得声称自己看过图。** 它会返回空结果（`EMPTY_OUTPUT_FALLBACK`）或幻觉 —— 已知它会把代码里根本不存在的「心形图案 / 白色发带」说成存在。**失败两次必须换路径，不要重复同一调用。** 引用它的结论时必须注明「间接证据，未人工目视」。

### 4.2 三个核心指标陷阱（另外 4 条固化在 §6.5，累计 7 条）

1. **眼距定义陷阱**：
   - 按「瞳孔间距 / 眼全宽」算 = 0.081 / 0.0416 = **1.95** → 结论「眼距过宽，要改」 ❌
   - 按「内眼角间距 / 眼全宽」算 = 0.0394 / 0.0416 = **0.95** → 结论「标准，不要改」 ✅
   - **同一份数据，相反结论。** 美术上的「眼距」几乎总是指内眼角间距。**先定口径再下结论。**
2. **连通分量必须膨胀**：体素重网格后顶点间距约 5mm，裸 2mm 栅格会把连续的单一表面切成 **17~103** 块（假阳性）。必须对每个点做 **r=3mm 膨胀**再做 8 邻域连通，基线单管才会正确归为 1 个分量。
3. **不能按 x 排序看间隙判断分叉**：闭合环在 x 方向天然断成两段（左右侧），单管手掌会报 5~8 段。**必须用 (x,y) 平面连通分量。**

### 6.1 袖口：47mm 而非 53mm（数值偏离成立，理由已更正）

- 初稿判据：「袖口半径 = 上臂 + 7~10mm = **52~55mm**」→ 计划取 **53mm**。
- 实际取 **47mm**。独立复算：袖口 47.0mm、与**同轴同面**上臂中位半径 **38.82mm** 的间隙 = **8.18mm** ∈[7,10] ✅。
- **为什么初稿的 53mm 是错的**：初稿拿 `body.arm()` 在 z=1.220 的**参数半径 45mm** 当上臂，但袖口实际落在上臂**下段**（中心 z=1.110），那里实测中位半径只有 **38.82mm**（max 42.34 / min 34.43）。

| 减法基准 | 47mm 的结果 | 53mm 的结果 | 判定 |
| --- | --- | --- | --- |
| 参数半径 45mm（错） | 2.0mm → 「太小」 | 8.0mm → 「正好」 | **两个判断都错** |
| 同轴同面 38.82mm（对） | **8.18mm** → 正常 | **14.18mm** → **超上限** | 47mm 正确，53mm 过松 |

- 因此 `outfit.py:124-140` 原注释「53mm 会切进上臂」是**方向性错误**（53>47 只会更松），已改为与实测一致。
- **留下的判据**：只看「同轴同面间隙 ∈[7,10]mm」，**不看袖口半径绝对值**。

### 6.3 脚趾：四口径互证（裸 z 切片的上限就是 1）

摘要（完整表见 §2.4.2）：

| 口径 | 实测 | 能否用作判据 |
| --- | --- | --- |
| ① 裸 z 切片（不限 y） | **1** | ❌ 解剖上限就是 1（脚趾必须连着脚掌），**不是缺陷** |
| ② z+y 带（主指标） | **3** | ✅ 达标（≥2） |
| ③ 更窄 y 带 | **1** | ❌ 把趾缝切掉了，会误判失败 |
| ④ y=100mm 半带 | **3** | ✅ 交叉验证，与 ② 一致 |

**要点**：只用 ① 判，会把「脚趾已做对」误判成「没做」；只用 ③ 判，会把做对的脚判成失败。**判脚趾必须同时报 ② 和 ④。**

**五条实测坑（别重踩）**

1. **开着 Solidify/Armature 烘焙 AO 会全 0**（`bake_ao` 已临时 mute 修改器）。
2. **toon 的 albedo 是 base × ramp light**，不是 ramp light；只取后者会让头发从深棕变灰紫。
3. **`image.save()` 对 float 缓冲是线性直通**，必须手写 sRGB，否则引擎加载偏暗。
4. **UV 岛必须 dilate**（12px），否则双线性采样采到背景，全身出现黑缝。
5. **glTF 导入器会多生成一个 Icosphere** 骨骼辅助网格；它不在 glb 里，回读统计按白名单过滤。
