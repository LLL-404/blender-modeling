# Blender 5.2 手册学习笔记

> 手册包 `docs/blender_manual_html.zip`（353.7 MB）→ 建成本地全文索引 → 用手册原文**逐条核对本项目代码里的既有判断**。
> 索引与 zip 都不入库（GitHub 单文件上限 100 MB），工具入库，随时可重建。

## 0. 手册包是什么

| 项 | 值 |
|---|---|
| 来源 | docs.blender.org 离线 HTML，`blender_manual_v520_zh-hans` |
| 体积 | 353.7 MB / 5929 个文件 / 2361 个 HTML |
| 正文 | **2356 页 / 154.3 万字**（已剔除 404/search/genindex 等导航页） |
| 交叉引用 | `objects.inv` 8274 条，其中 **`bpy.types.*` 3311 条** |
| 索引 | `docs/manual/manual.db`，18.0 MB，SQLite FTS5，重建 **4 秒** |

它是**概念手册**，不是 Python API 参考（后者是 docs.blender.org/api 的另一套）。所以它补的正好是 `BlenderAPI/catalog/` 缺的那一半：

| 层 | 回答什么 | 怎么来的 |
|---|---|---|
| `catalog/` | 有什么 API、参数叫什么、默认值多少 | 在跑着的 Blender 里扫描 |
| **手册索引** | **这个参数什么意思、什么时候该用哪个** | 官方文档原文 |
| `selftest.py` | headless 下到底能不能用 | 实机断言 |

## 1. 用法

```bash
python docs/manual_index.py build                      # 重建索引，约 4 秒
python docs/manual_index.py "实体化 厚度 偏移"          # 全文检索（多词 AND，全落空自动退 OR）
python docs/manual_index.py --api bpy.types.SolidifyModifier   # API 名 → 手册页（短名也可以）
python docs/manual_index.py --show modeling/modifiers/generate/solidify.html
python docs/manual_index.py --selfcheck                # 回归自检 10 项
python docs/manual_index.py --stats
```

退出码：`0` 有结果 / `1` 无结果 / `2` 参数错 —— 和 `grep` 一个约定，脚本里能直接判。

索引缺失时**自动重建**（有手册包就 4 秒建好，没有就打印获取办法），所以新环境第一次查询不会卡在 build 提示上。路径可用 `BLENDER_MANUAL_ZIP` / `BLENDER_MANUAL_DB` 覆盖。

两点实现上的坑（已写进代码注释）：

- **中文必须逐字切词**。SQLite FTS5 的 `unicode61` 把整串汉字当一个 token，「厚度模式」是一个词，搜「厚度」永远不命中。入库前在每个 CJK 字符两侧插空格，查询时同样切碎再包成短语。
- **只解析 `<article>` 那一小段**。每页 440 KB 里有 400 KB 是侧边栏导航树；先切正文再交给解析器，整体快一个数量级（2356 页 4 秒）。

## 3. 用手册核对本项目的既有实现

这三条都是代码注释里早就写死的结论，这次用手册原文 + 实机复测双重复核。

### Solidify 的 `offset` 符号

`lib/look.py:313` 注释写「offset=-1 时壳朝内长，完全被本体挡住，offset=+1 才有轮廓线」。

| offset | 手册原文 | 实机复测（法线 +Z 的平面，thickness=0.02） |
|---|---|---|
| `+1` | 「介于 -1 到 1…内部和外部是由面法向决定的」 | z ∈ `[0, +0.0200]` → **沿法线，外侧** |
| `0` | 「设置为 0.0 时，实体化后的输出将以原始网格为中心」 | z ∈ `[-0.0100, +0.0100]` → 居中 |
| `-1` | 同上 | z ∈ `[-0.0200, 0]` → **逆法线，内侧** |

**结论：一致。** 顺带确认 `lib/outfit.py:306` 那句「Solidify 0.004 / offset 0 → 外表面 +2mm」也对（0.004 ÷ 2 = 2 mm）。

### `use_rim`（边缘/填充）

手册：「边缘 / 填充 —— 在面的边线上创建内表面」。

| 设置 | 开放网格的面数（原 4 面） |
|---|---|
| `use_rim=True` | 4 → **16**（上下各 4 + 侧壁 + 封口） |
| `use_rim=False` | 4 → **8**（只有上下两面，不封口） |
| `use_rim_only=True` | 4 → **12** |

`lib/look.py:332` 已经写了 `use_rim = False` —— 描边壳不生成封口边，这是之前反复踩「开口边被描边勾成黑线」后改的，跟手册定义对得上。

### catalog 与实机的默认值

| 属性 | `catalog/api.json` | 实机 |
|---|---|---|
| `thickness` | 0.01 | 0.01 |
| `offset` | -1.0 | -1.0 |
| `use_rim` | True | True |
| `use_rim_only` | False | False |
| `material_offset` / `_rim` | 0 / 0 | 0 / 0 |

7 项全对，`use_flip_normals` 也确实存在（默认 False）。

## 4. 手册里有、我们没用上的东西

按对本项目价值排序。

| 手册功能 | 页面 | 为什么值得用 |
|---|---|---|
| **面朝向叠加层** | `modeling/meshes/editing/mesh/normals.html` | 红/蓝直接标出反了的面。上一轮排查破面时用的是射线探针 + 分色渲染（改脚本、跑 Blender、看日志），这个在视口里一眼就看见 |
| **按角度平滑修改器** | `modeling/modifiers/normals/smooth_by_angle.html` | 4.1 起 `Mesh.use_auto_smooth` 已移除，替代物就是它。`catalog` 里查不到 `use_auto_smooth` 时，手册能解释为什么 |
| **简单模式 vs 复杂模式** | `modeling/modifiers/generate/solidify.html` | 「如果相邻面的法线不指向同一个大方向，**简单模式将无法固化这些面的边界**」—— 鲍伯壳正是开口弧 + 折返几何，属于这条警告描述的情形。复杂模式能保证输出是流形 |
| **三角面→四边面** `Alt-J` | `modeling/meshes/editing/face/triangles_quads.html` | 「使用角度阈值防止生成畸形四边形，意味着部分三角形可能保持原状」—— 解释了残余三角面的来源，不是脚本 bug |
| **按距离合并** | `modeling/meshes/editing/mesh/merge.html` | 收口封缝的常规手段，比手工算顶点位置可靠 |

## 5. 检索词对照（中文术语不总等于手册用词）

搜不到时先换词，这是全文匹配的固有限制，不是索引坏了。

| 你会搜 | 手册写作 | 位置 |
|---|---|---|
| 重新网格化 / remesh | **重构网格** | `modeling/modifiers/generate/remesh.html` |
| 自动平滑 | **自动平滑着色** → 按角度平滑修改器 | `scene_layout/object/editing/shading.html` |
| 合并顶点 / 焊接 | **合并 → 按距离** | `modeling/meshes/editing/mesh/merge.html` |
| 三角化 | **面三角化** | `modeling/meshes/editing/face/triangulate_faces.html` |
| 反法线描边 / 卡通描边 | **手册没有这个概念** | 最接近的是 Freestyle 描边（`render/freestyle/`），那是渲染期描线，不是同一回事 |
| 无头 / headless | **从命令行渲染** / `-b, --background` | `advanced/command_line/` |

## 6. 索引的已知限制

| 限制 | 说明 |
|---|---|
| 不懂同义 | 「重新网格化」搜不到「重构网格」，要靠 §5 的对照表或换词 |
| 是 5.2 中文版译文 | 译文偶有生硬（Node Wrangler → 「节点牧人」），个别术语与社区习惯不一致 |
| 不含 Python API | 函数签名、参数类型仍以 `BlenderAPI/catalog/api.json` 为准 |
| 不证明 headless 可用 | 手册描述的是界面操作；脚本里能不能用要跑 `selftest.py` |
